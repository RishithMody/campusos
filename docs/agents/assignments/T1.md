## Objective

Define the architecture and publish the shared contracts that T2 (backend), T3 (GPU), T4 (ML),
and T5 (frontend) all build against **in parallel, without talking to each other.**

This is the highest-leverage task in the project and the one where mistakes are most expensive.
Every ambiguity you leave here becomes a merge conflict or an integration failure in T7, at the
point in the schedule where there is no time to fix it. Three agents will code against these
files from memory-less sessions; the contracts have to answer their questions without you.

## File ownership

**You own:** `docs/architecture.md`, `contracts/`, `docs/adr/`
**Read-only:** everything else. You do **not** write feature code.

## Acceptance criteria

- [ ] `docs/architecture.md`:
  - [ ] Component diagram (frontend ↔ backend ↔ agent runtime ↔ inference ↔ Postgres/Redis)
  - [ ] Request flow for one complete negotiation, end to end
  - [ ] Data model overview (students, calendars, commitments, grants, negotiations, transcripts)
  - [ ] **Trust boundaries** drawn explicitly, and the one place the privacy guarantee is enforced
  - [ ] How a student's agent is authorised to act for them, and the limits of that authority
- [ ] `contracts/agent-protocol.schema.json` — the agent-to-agent message envelope:
      sender identity, represented student, scope of authority, **disclosure level**, intent
      (`propose` / `counter` / `accept` / `reject` / `escalate`), payload, trace ID
- [ ] `contracts/api.openapi.yaml` — the REST surface between frontend and backend
- [ ] `contracts/negotiation-state.schema.json` — the LangGraph state the frontend visualises
- [ ] `contracts/inference.md` — the inference interface, written so that the **mock and vLLM
      are drop-in replacements for each other**. T2 and T4 both code against this; T3 implements it.
- [ ] **Disclosure levels enumerated and defined**: for each level, exactly what may and may not
      be revealed. This is the core product guarantee — "busy 2–4pm" is permitted,
      "therapy at 2pm" is not. Everything downstream tests against this definition.
- [ ] Every schema is valid and parses: `./scripts/ci/validate_contracts.py`
- [ ] Each schema has a valid example fixture **and** a deliberately invalid one, with the
      invalid one correctly rejected
- [ ] File ownership for T2–T5 declared and verified **disjoint** — no two tasks own one path
- [ ] Assignment files for T2, T3, T4, T5 written (fill in their "Context the agent cannot
      infer" sections from this task's output), and T2/T3/T4 moved to `READY` in the task graph

## Required tests

- `./scripts/ci/validate_contracts.py` passes
- Valid fixtures validate; invalid fixtures are rejected

## Context the agent cannot infer

- Phase 1 must run **entirely on mocks**: three student agents negotiating with no GPU. Design
  the inference interface so this is true from day one, not retrofitted.
- The negotiation state is a *product* surface, not an implementation detail — T5 renders it
  live. Design it to be readable and serialisable, and version it.
- Keep contracts as small as the demo needs. Every field is a field three agents must implement
  and QA must test. Scope creep here multiplies by four.
- Prefer additive versioning from the start (`v1` in the path) so a late change does not break
  agents mid-flight.

## Out of scope

- Any implementation in `backend/`, `frontend/`, `ml/`, `infra/`
- Starting T2–T5 agents yourself — you write their assignments; the human launches them

## Definition of done

3. Committed on `task/T1-architecture`
4. `./scripts/agents.sh handoff T1` completed
5. Reviewed (`./scripts/agents.sh review T1` → `codex`), status `REVIEW`
6. **Do not merge.** The human merges, then T2/T3/T4 can start.
