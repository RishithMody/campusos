## Objective

Build the synthetic negotiation dataset and the evaluation harness, then measure the **base**
Qwen3 8B — before any fine-tuning exists. Without a reproducible baseline, T6 cannot claim an
improvement, and "our fine-tune made it better" becomes an unfalsifiable statement.

Define the metrics and commit them **before** the first measurement, so the baseline cannot be
retrofitted to flatter a later result.

## File ownership

**You own:** `ml/`, `tests/ml/`
**Read-only:** `contracts/`
**Never touch:** `backend/`, `frontend/`, `infra/`

## Acceptance criteria

- [ ] `ml/metrics.md` written and committed **before any model is run**, defining:
      negotiation success rate, rounds to convergence, constraint violations,
      **privacy leakage rate**, schema-valid output rate, latency — each with its exact
      computation, not just a name
- [ ] Synthetic negotiation dataset generator: overlapping commitments, soft vs. hard
      constraints, asymmetric flexibility, privacy-sensitive reasons for unavailability
- [ ] Generator is **deterministic for a given seed**; generator and seed documented in
      `ml/data/README.md` so any dataset is reproducible
- [ ] A held-out test split that is **never trained on** and is kept separate from T6
- [ ] Baseline Qwen3 8B measured on the held-out set — **or** an explicit, honest record of
      why it could not be (e.g. GPU approval not granted, cluster unavailable)
- [ ] Results in `ml/runs/<timestamp>-baseline/`: config, git commit, dataset hash,
      metrics JSON, logs. A run without its config is not a result.
- [ ] The eval harness runs end to end against the **mock** inference client with no GPU, so
      it is testable in CI
- [ ] Privacy-leakage scorer implemented against the disclosure levels in
      `contracts/agent-protocol.schema.json` — this is the metric that matters most to the product
- [ ] No weights, checkpoints, or large datasets committed

## Required tests

- [ ] `pytest tests/ml/` green
- [ ] Determinism: same seed → byte-identical dataset
- [ ] Eval harness scoring on fixed fixtures (known input → known score)
- [ ] Privacy-leakage scorer correctly flags an over-disclosing response, and does **not** flag
      a compliant one (test both directions)
