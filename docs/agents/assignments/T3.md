## Objective

Serve Qwen3 8B on the H200s behind an OpenAI-compatible endpoint that implements
`contracts/inference.md`, so the backend's mock client can be swapped for real inference with
no code change. Make it reproducible from committed config, safe to restart, private, and
measured.

## Acceptance criteria

- [ ] `infra/validate_env.sh` — **read-only** report: driver version, CUDA runtime, PyTorch,
      vLLM, `nvidia-smi` topology, NVLink/P2P, VRAM per GPU, and **existing GPU processes**.
      Idempotent; mutates nothing; safe to re-run.
- [ ] Documented, working compatibility matrix (driver ↔ CUDA ↔ PyTorch ↔ vLLM) for these H200s.
      Version skew here is the most common way a hackathon loses a day.
- [ ] vLLM serves Qwen3 8B with an OpenAI-compatible API, from **committed config** under
      `infra/`, not ad-hoc shell flags
- [ ] **`max_num_seqs` ≤ 256.** `512` has caused GPU wedging on this hardware and is forbidden.
- [ ] `--gpu-memory-utilization` set explicitly with headroom; tensor-parallel size explicit
- [ ] **Graceful teardown verified:** stop and restart leaves no wedged GPU and no orphaned
      process. A killed vLLM that wedges a GPU costs more time than stopping cleanly.
- [ ] Endpoint bound to **localhost or a private interface only**, reached via SSH tunnel,
      with authentication in front. Never `0.0.0.0` on a routable interface, never a public tunnel.
- [ ] Dockerfiles build; **mock-mode `docker compose up` works on a laptop with no GPU**
- [ ] `infra/benchmarks/` records tokens/sec, time-to-first-token, p50/p95/p99 latency under
      concurrency, VRAM headroom, GPU utilization — **each with the exact command that produced it**
- [ ] No SSH keys, credentials, `.pem` files, or hostnames-with-secrets in Git; host comes from
      an environment variable or parameter with no default

### The disclosure ladder — the specification your privacy tests are written against

| Level | May contain | May never contain |
|---|---|---|
| `none` | a yes/no on one proposed time | any enumeration of busy times |
| `free_busy` | intervals busy / free / tentative | reason, category, label, location, participants |
| `category` | `free_busy` + `academic` \| `work` \| `social` \| `personal` | free text of any kind |
| `full` | `category` + a human-readable label | — needs an explicit, logged, scoped grant |

`"busy 2-4pm"` is permitted at `free_busy`. `"therapy at 2pm"` is only ever possible at `full`.
Default for a new negotiation is `free_busy`. Implement the enum exactly; do not reinterpret it.

**The category enum is deliberately blunt.** `personal` absorbs health, therapy and family. Never
add `medical`, `health` or similar — a category that reveals *why* someone is busy defeats the
ladder. **Reasons are a closed vocabulary** (`reason_code`), never prose: free-text explanation
is the most common way a careful system leaks.

### Decisions already made that you must not relitigate

- **Disclosure is enforced server-side, on egress, in one place** (the privacy service). Not in
  agents, not in clients. A client bug must not become a privacy breach.
- **Identity comes from the validated token, never from a client-supplied id**, on every path.
- **Cross-student reads need an explicit grant row and write an audit record.** No implicit sharing.
- **`student_ref` is a per-negotiation pseudonym**, never a name, email or stable id.
- **No MCP anywhere.** Cubbie's sandbox does not support it. The Skill boundary is HTTPS/443.
- **Agent-to-agent traffic never routes through Cubbie** — Cubbie texts only its own student.
- **The negotiation loop is bounded** (`max_rounds`, ceiling 20). Failure to converge is a
  product outcome that escalates to a human, not an error to retry away.
- **Contracts are frozen.** Need a change? Write it in your handoff, set `REVIEW`, and stop.

### Specific to T3

- You own **serving**, not the adapter: `infra/vllm/` — config, launch, binding, teardown and
  benchmark. The Python that speaks to your endpoint lives in `backend/inference/vllm_client.py`
  and belongs to T2, because `backend/` is not yours to edit. Fix the endpoint contract the
  adapter codes against — URL shape, model name, timeouts, health semantics — and write it into
  your handoff; that handoff is what T2 implements against.
- Mock and vLLM must be **behaviourally substitutable**: same Protocol, same return shapes, the
  same four exceptions (`InferenceTimeout`, `InferenceUnavailable`, `InferenceSchemaError`,
  `InferenceRejected`) raised in the same situations. They are *not* required to be
  indistinguishable — they report different model names and different latencies, and T4's
  benchmark depends on being able to tell them apart. Substitutable in behaviour, not identical.
- `health()` on a down endpoint **returns** `healthy=False`; it does not raise.
- **The vLLM endpoint is never the public internet-facing host.** Cubbie's sandbox cannot reach
  an SSH-tunnelled endpoint, and the resolution is that Track 1 does not call our inference at
  all (ADR 0001). Do not "fix" this by exposing vLLM; that would need its own ADR and human
  approval.
- Cluster access details are still unknown to this repository (open question #2 in
  `docs/agents/status.md`). **Ask the human; do not guess a hostname.**
- Authoring configs and scripts needs no approval. **Running anything against the H200s needs a
  human-signed token in your assignment file.**
