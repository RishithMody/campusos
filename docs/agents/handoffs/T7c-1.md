## 1. Completed work

C1–C9 from `docs/integration/external-discord-connector.md` §8.1 now exist as an automated
suite: **67 passed, 1 skipped**, no Discord connection, no credentials, no production change.

The suite tests **our side** of the boundary an external connector will sit on. Nothing in it
depends on the connector existing, which is why it was writable today and why it stays useful
whichever connector arrives.

Three things it establishes that nothing established before:

- **The bot-reachable surface is pinned.** Every operation in the frozen contract is swept with
  one bot credential, and the reachable set must be exactly `{GET /health, POST /channels}`. A
  separate test asserts the sweep table covers every operation in `api.openapi.yaml`, so adding
  an endpoint to the contract fails this suite until someone classifies it.
- **The nine sentences are pinned across three copies.** The contract's markdown table, the
  `template_id` enum beside it, and `groupchat/render.py`'s dict must agree exactly. Nothing
  parsed that table before; the three could drift apart silently, and the table is the only
  thing standing between a group chat and free text.
- **`DiscordREST` is tested at all.** It had zero tests, despite being the component that
  decides how many people can read a room — which is what channel consent is consented *to*.

## 5. Known limitations

**C9's connector half is BLOCKED, with evidence.** The case is defined as "connector renderer
vs `render.py`, byte-identical". There is no connector. Rather than weaken it to something
passable, the test is written in full and gated on `CAMPUSOS_CONNECTOR_RESULTS` — a JSON file
mapping each corpus case id to the string that connector produced, or `null` if it refused.
That is the smallest interface that presumes nothing about the connector's internals or
language. It appears as a visible skip, carrying its reason, on every run.

**M7 survived, and it is an equivalent mutant, not a gap.** Removing
`if not isinstance(members, list)` from `DiscordREST.audience` changes nothing observable:
iterating a dict yields strings, `member["user"]` raises `TypeError`, and the surrounding
handler converts that to the same 503. The guard is belt-and-braces. Recorded because a
surviving mutant that goes unmentioned is how a suite quietly rots.

**F1 — the contract under-specifies `{agreed_slot}`.** `ChannelSummary` says only that it is
"formatted from the timestamps in the channel's own timezone". The actual format —
`%Y-%m-%d %H:%M %Z`, joined by an **en dash** — lives in `render.py` and nowhere in the
contract. A connector could be perfectly contract-conformant and still post a differently
formatted sentence. `conformance.json` now pins our formatting as the de-facto specification,
which is a workaround, not a fix. **A contract change is the real fix and is the Orchestrator's
call, not this task's.**

**What this suite does not prove.** Nothing about a real connector, which does not exist yet.
Nothing about live Discord — `FakeDiscord` and `httpx.MockTransport` throughout. It does not
test C10–C12, which are out of scope for C1–C9. It cannot prove a third-party connector never
composes prose; only that ours does not and that the backend will not hand it any.

**Scope boundary respected, deliberately.** `tests/live/discord/` (T7b) was not created and no
Discord credential was used, requested, or implied.

## 6. Decisions and assumptions

- **Harness duplicated rather than imported.** `tests/live/environment.py` already does this and
  T7b's notes call the duplication expected. A boundary test that broke because another suite
  changed its fixture would be a bad trade.
- **The corpus is hand-written from the contract's table, not generated from `render.py`.**
  Generating it would have made C9 circular: the renderer would be checked against itself. Every
  expected string was typed out from the contract and then matched on first run.
- **One line is allowlisted for the secret scanner.** The obviously-fake bot token constant in
  `test_discord_failclosed.py` carries `pragma: allowlist secret`, which is the hook's own
  documented escape hatch for a false positive. `--no-verify` was not used. (The scanner
  flagged this handoff too, for quoting that line — reworded rather than allowlisted, because
  a prose file has no reason to contain an assignment that looks like a credential.)
- **Owner requirements 6, 7, 8 and 10 are not C-cases.** They were given directly by the owner
  and are labelled as such in the test docstrings, so provenance stays honest. Requirement 8 in
  particular produced the largest single file here, because `DiscordREST` had no coverage at all.
- **Ownership deviation.** `tests/` is the QA / Security Reviewer's and CLAUDE.md §9 says the
  Orchestrator does not implement. The owner directed this explicitly. The work is therefore on
  a task branch with this handoff and goes to independent review before any merge: the
  authorship convention bent, the review loop did not.
