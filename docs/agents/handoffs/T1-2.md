## 1. Completed work

**F3 — a real disclosure hole, now closed.** The reviewer demonstrated that the schema this task
exists to provide would accept a `free_busy` message carrying a `full` availability envelope
labelled `therapy`. The availability schema enforced the ladder *inside* its own envelope;
nothing bound that to the envelope carrying it. Three levels occur in one message — the ceiling
the student granted, what the message claims, what the payload holds — and they are now checked
as one chain. `scope.max_disclosure_level` is required (absent used to validate, making
"unspecified authority" indistinguishable from "full authority"). An `accept` now requires
`in_reply_to` and `granted_by: per_negotiation`: a standing preference set once is not consent
to a specific commitment, which the schema's own prose already claimed and did not enforce.

**F1 / F2 / F5 — the contracts described workflows no independent client could complete.**

- *Approvals could not be discovered before deciding.* Informed consent was therefore impossible:
  the only description of consequences arrived in the response, after the decision. State now
  carries `pending_approvals` — id, action, expiry, and `discloses` with the preview, the exact
  recipients and the field paths. Decisions bind to `state_version`, so a stale approval is a
  `409` instead of a silent yes to something the student never saw.
- *Creation required `stu_` refs that only exist once the negotiation does.* Creation now takes
  durable `cnt_` contact handles and the server mints the per-negotiation pseudonyms. Two
  identifiers with opposite lifetimes — the identity model needed this regardless; the review
  just made the gap visible. `viewer` tells a participant which pseudonym is its own.
- *The frontend had no list, no disclosed payload and no chat route.* Added `GET /negotiations`
  (with `awaiting_me`), `transcript[].disclosed`, and `POST /me/chat`. T5 now carries a table
  mapping each acceptance criterion to the endpoint serving it, so "invent an API" is not a
  reading it supports.

**F4 — a participant-filtered document is not permission to broadcast it to a room.** T9 was told
both to filter for the channel and never to filter. The channel is now a registered disclosure
audience the backend owns, capped at `free_busy` by contract, confirmed by participating members.
The bot posts `ChannelSummary.text` verbatim and never reads `NegotiationState`.

**F6 — `/health` was the single unauthenticated path**, contradicting CLAUDE.md §7 and this
document's own no-exceptions claim. Now authenticated; container probes use the internal port.

**F7 — the inference contract disagreed with CI and with itself.** One name
(`CAMPUSOS_INFERENCE_MODE`, matching CI), no default. T3 cannot own `backend/inference/` because
it cannot edit `backend/`: T2 owns the adapter, T3 owns serving in `infra/vllm/`. Dropped the
requirement that mock and vLLM be indistinguishable *by timing* — T4's benchmark depends on
telling them apart; behavioural substitutability is the useful property.

**Unprompted, same class:** a grant could be given and not taken back. `DELETE /grants/{id}`
revokes, and revocation drops open streams — the natural implementation checks the grant only at
stream open, and keeps leaking to a long-lived connection afterwards.

**On `main` (protected paths, committed separately as `eef3026`):** the validator now checks
`api.openapi.yaml` against the OpenAPI 3.1 specification and bundles every `$ref` into our own
namespace from `contracts/` first. It previously parsed YAML, saw three keys and called that
"valid OpenAPI" — a document can clear that bar and be rejected by every code generator the
frontend would use. A dangling `$ref` is now a reported error rather than a silent fetch from
`campusos.dev`, a host that does not resolve.

## 5. Known limitations

- **Nothing here is running.** The schemas structurally reject a set of over-disclosures and that
  is a real second net, but the primary guarantee is the server-side filter on egress, and it
  does not exist until T2. No runtime privacy claim has been tested against a service. The
  reviewer was right to separate "specified" from "tested" and that distinction now appears in
  `docs/architecture.md` §8 rather than only in a review file.
- **Channel consent is collected once, at registration.** Someone who joins the Discord channel
  afterwards is inside an audience they never confirmed. The `free_busy` cap bounds the damage;
  it does not solve it.
- **The ladder is enforced structurally only where levels are declared.** A payload whose
  `availability` is absent is unconstrained by those rules, because there is nothing to compare.
  Runtime grant checking remains mandatory and is T2's.
- **`state_version` is specified, not implemented.** Whether approvals are genuinely atomic
  against concurrent state changes is T2's to demonstrate.
- No `tests/` directory exists yet, so there is no integration suite to regress.

## 6. Decisions and assumptions

- **`/health` authenticated rather than granted an exception.** CLAUDE.md §7 states the rule
  without one. An exception is a human decision and would need an ADR; defaulting to the
  documented rule is the conservative reading. If you want an unauthenticated probe, say so and
  it becomes a one-line change plus an ADR.
- **Channel ceiling capped at `free_busy` in the contract, not by convention.** `category` and
  `full` describe *why* someone is unavailable, and a group chat is the wrong audience for that
  at any consent level a bot could plausibly collect.
- **Contact handles are a new concept.** The alternative was letting clients reuse a `stu_`
  across negotiations, which is precisely the correlation the pseudonyms exist to prevent.
- **`accept` now requires a per-negotiation grant.** Beyond the literal finding, but the same
  defect class: the schema's prose already claimed it.
- **Aligned the contract to CI's env name** rather than changing CI — `.github/**` is protected
  and the cheaper change was the one that touched no protected file.
