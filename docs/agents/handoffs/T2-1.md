## 1. Completed work

Every frozen OpenAPI operation is registered under /v1 with bearer authentication.
The backend now implements contact handles, negotiation-local student pseudonyms,
explicit human grants, availability submission, bounded LangGraph negotiation,
human approvals, commitments, filtered state/transcript reads, chat and state SSE,
and channel consent. Three students with conflicting availability converge after
three proposals; no-overlap, exhausted rounds and unavailable inference escalate.

The privacy service filters actual outbound payloads and strips private notes.
Cross-student disclosure requires live scoped grants and appends audit records.
Inbound malformed/unauthorized/over-disclosing messages return structured
400/403/422 errors. Partial approvals remain representable, stale decisions are
409s, and agent accepts require a recorded human approval. Open streams terminate
after their grant is revoked or expires.

PostgreSQL models and migrations hold durable state; Redis holds only expiring
version markers and pub/sub notifications. The injectable inference Protocol,
mock and vLLM adapter share the frozen types/errors and require explicit selection.

Discord registration verifies the guild-bound bot's permissions. Human member links
use previously verified OAuth identities. Every participant approves each channel
binding; growth requires re-consent and withdrawal ends posting. Superseded approvals
cannot approve replacement audiences. Summaries contain only allowlisted template
IDs and typed slots; the summary module has no inference dependency.

## 5. Known limitations

- Redis verification uses fakeredis, not a live Redis server. Discord permission
  calculation is unit-tested but no real Discord account/channel was contacted.
  vLLM uses HTTP mock transports; no live model or GPU was contacted.
- Account/login issuance is outside the frozen REST surface. A trusted operator
  provisions issuer subjects. The OAuth helper verifies Discord /users/@me but the
  operator must bind that student's OAuth ceremony to the authenticated CampusOS
  subject. Do not expose this helper publicly or let bots assert identity mappings.
- Human tokens rely on a trusted issuer; possession of the server signing key is
  administrative authority. A signed human-kind claim is not proof of a human
  ceremony unless the issuer enforces that. Never distribute this key to clients.
- Commitments are local durable rows. No Google Calendar writes, actual Discord
  posts, external messages, or Cubbie ability calls are performed here.
- Per-worker async serialization prevents a synchronous DB row lock from blocking
  its own event loop while inference is awaited. PostgreSQL coordinates workers.
  This favors prototype correctness over throughput.
- Redis publish can fail after a PostgreSQL commit: the caller gets 503 and must
  re-read before retrying. Streams also poll durable state for lost notifications.
- Availability must enumerate explicit free slots, match the negotiation window,
  and keep slots within it. Missing intervals are never assumed free. Candidate
  times come from interval boundaries; this is a bounded solver, not an optimizer.
- Chat uses closed intents and structured status, not arbitrary user prose sent
  to a model. The caller's own private notes are returned directly only to them.
- Generated DTOs omit conditional allOf rules. Runtime always validates the complete
  original JSON Schema first. All frozen positive/negative fixtures are tested.
- Discord supports guild text channels, requires Guild Members intent, and counts
  members with actual view permission. Same-size audience substitution remains the
  frozen contract's documented limitation. Discord membership snapshots cannot be
  locked atomically across consent preview and a client's later post.
- No independent T2 review has occurred. T1's waiver does not waive T2 review.

## 6. Decisions and assumptions

The authoritative board's READY state and T1 REVIEW_WAIVED dependency resolution
supersede stale BLOCKED prose. Frozen API/assignment requirements supersede the
architecture document's older free-text channel summary description.

Grant creation is human-only; invitation alone permits no calendar sharing.
Approvals bind to a version, and undecided previews refresh after state changes;
decided approval timestamps/versions remain immutable. Superseded consent records
are retired as system actions, not represented as human approvals. Audit rows are
only appended by application code.

Inference configuration has no default; external LangSmith tracing is refused
at environment startup. The vLLM adapter embeds frozen local schema references
rather than asking the server to fetch public schema URLs.
