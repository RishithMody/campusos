## 3. Correction to attempt 1

**I was wrong to call M7 equivalent, and the reasoning was lazy.** I checked that a non-empty
dict raises `TypeError` deeper in and concluded the guard was redundant. I did not try `{}`.
An empty object iterates zero times, never raises, reaches `len(members) < 1000`, and returns
a well-formed audience of **size 0**. The review's counterexample is correct and the handoff's
§5 claim should be read as withdrawn.

The direction matters: `channel_summary` only re-asks for consent when the audience **grew**.
An undercount can never trigger it, so it is the dangerous direction, not the safe one.

## 4. Two new production defects found while fixing this

Neither is fixed here — the review was explicit that this repair touches tests and evidence
only. Both are raised for the Orchestrator.

**P1 — an empty member list yields an audience of zero, guard or no guard.** `[]` is a
well-formed list, so `isinstance` passes, and `audience()` returns `size 0`. The bot itself
must be able to view the channel (`context()` has already insisted), so zero is arithmetically
impossible and means the page was not understood. Recorded as a **strict xfail**, so it flips
to a failure the moment production is fixed:

```
XFAIL test_an_audience_of_zero_is_never_returned
```

This is the same hazard as M7 reached through a path the guard does not cover. A plausible
trigger is Guild Members intent being disabled — exactly the condition T7b is meant to probe.

**P2 — a malformed channel document escapes as `AttributeError`, not `Problem(503)`.** A 200
whose body is not an object reaches `room.get("guild_id")` and raises `AttributeError`, which
the surrounding handler does not catch. It would surface as a 500 rather than the service's
fail-closed 503. No audience is produced either way, so consent cannot be computed from a bad
answer. `test_a_malformed_channel_document_produces_no_audience` accepts both outcomes, so
fixing production will not break it.
